# AXI Interface — DexterLab Parser (Version 1.0)
The DexterLab Command Parser communicates with the AXI_FULL execution engine through
a simplified AXI-like interface. This interface is designed to support single-beat,
multi-beat, burst, wrap, fill, and poll operations with consistent timing and
deterministic behavior.

This document describes:
- AXI command structure
- handshake signals
- response signals
- multi-beat sequencing
- error handling
- interaction with the parser FSM

---

## 📌 AXI Command Structure
Each AXI command generated by the parser is represented by:

```vhdl
cmd_out.cmd_type : std_logic_vector(7 downto 0)
cmd_out.cmd_id   : std_logic_vector(C_ID_WIDTH-1 downto 0)
cmd_out.addr     : std_logic_vector(C_ADDR_WIDTH-1 downto 0)
cmd_out.len      : std_logic_vector(15 downto 0)
cmd_out.data     : std_logic_vector(C_DATA_WIDTH-1 downto 0)
cmd_out.atomic   : std_logic

Key fields
cmd_type — identifies the AXI operation

cmd_id — unique ID for matching responses

addr — base address

len — number of beats (multi-beat commands)

data — write data

atomic — atomic mode flag

📌 Handshake Signals
Command handshake
s_cmd_valid — asserted by the parser when a new command is ready

cmd_ready — asserted by AXI_FULL when it accepts the command

Rule:

s_cmd_valid is asserted only when entering an AXI-related exec_ state*.

This ensures:

one command per state entry

no duplicate requests

clean handshake

📌 Response Signals
AXI_FULL returns responses through:

Data response
rsp_in.rsp_valid

rsp_in.rsp_data

rsp_in.rsp_last

rsp_in.rsp_id

Mapped internally to:

s_ack_data — valid data beat

s_ack_end — last beat of multi-beat operation

Error response
rsp_in.rsp_err_valid

rsp_in.rsp_err_code

rsp_in.rsp_err_info

rsp_in.rsp_err_id

Mapped internally to:

s_ack_err — error detected

📌 Multi‑Beat Sequencing
Multi-beat commands use:

s_data_index — current beat index

s_mc_cur.len — total beats

rsp_in.rsp_last — marks final beat

Address increments automatically:

Codice
addr_next = addr + (C_DATA_WIDTH / 8)
Used by:

FIFO

BURST

WRAP

FILL

DUMP

📌 Error Handling
AXI errors are decoded using:
vhdl
decode_err(rsp_in.rsp_err_code, err_msg, err_flag);
The parser logs:

error code

decoded message

beat index

address

Error counters:

s_axi_error_count

s_burst_error_count

s_wrap_error_count

s_fill_error_count

s_poll_error_count

s_dump_error_count

📌 AXI Behavior per Command Type
BASE (READ / WRITE / CHECK)
Single beat.
FSM waits for:

s_ack_data (success)

s_ack_err (error)

FIFO
Multi-beat.
FSM increments s_data_index until:

rsp_in.rsp_last = '1'

BURST / WRAP
AXI burst semantics.
Identical to FIFO but with AXI burst rules.

FILL
Writes repeated data.
Uses data_array(0) for all beats.

POLL
Uses AXI responses to evaluate:

masked value

toggle behavior

retry

timeout

DUMP
Reads memory and logs each beat.
Supports file output.

📌 Interaction with the FSM
AXI interface behavior is tightly coupled with FSM states:

next_cmd selects the correct exec_* state

each exec_* state asserts s_cmd_valid once

AXI responses drive:

beat progression

retry logic

timeout logic

error detection

state transitions
